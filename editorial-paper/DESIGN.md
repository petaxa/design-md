# Editorial Paper — DESIGN.md

## 1. Visual theme

白い紙面を濃いインクで編集した技術冊子のようなデザイン。余白、文字の大きさ、細い罫線で情報の順序を示す。画面、文書、資料など媒体を問わず、内容が主役になる静かな見た目を目指す。

キーワードは **編集的・端正・温かい紙・明快な階層**。装飾や色面よりも、組版と配置の精度を優先する。

## 2. Principles

### 位置と文字で階層をつくる

小さな現在地、明確な主題、控えめな補足の順に視線が動くようにする。主題は大きさと太さで示し、色付きのカードやバッジを階層づけの主な手段にしない。ひとつの画面や区画で最も強い要素はひとつに絞る。

### 余白を内容として扱う

情報を詰めて空白を埋めない。左上の短いラベル、中央寄りの主題、下方のメタ情報を使うときは、離れた要素がつくる緊張感を保つ。要素が少ない場面ほど余白を広くとる。

### 罫線で構造を示す

細い水平線で見出し、行、区画の始まりや終わりを示す。線は揃え、同じ意味には同じ太さと色を使う。枠線で四方を囲むより、一辺の罫線を優先する。

### アクセント色には意味を持たせる

ティールは現在位置、選択状態、進行方向、コードのプロンプトなど、意味のある箇所にだけ使う。見出し全体や大きな背景を彩るためには使わない。

## 3. Color

| Token | Value | Role |
| --- | --- | --- |
| Paper | `#fffdfa` | 主な背景。わずかに温かい白 |
| Warm paper | `#f6f1ea` | 周辺の背景、控えめな区画差 |
| Ink | `#121722` | 見出し、本文、主要な線 |
| Muted ink | `rgba(48, 47, 44, 0.60)` | 補足、番号、メタ情報 |
| Rule | `rgba(123, 116, 104, 0.46)` | 罫線 |
| Accent | `#2f7f7a` | 選択、進行、操作の手がかり |
| Code background | `#151a22` | コードやコマンドの背景 |
| Code ink | `#e9e4d8` | コードやコマンドの文字 |

大部分を Paper と Ink で構成する。Warm paper は面の切り替えを穏やかに示すときだけ使う。背景に暖色のグラデーションや微細なドットを重ねる場合は、文字より目立たない低いコントラストに抑える。意味上の必要がなければテクスチャを省いてよい。

Muted ink は小さな補助情報向け。長い本文や重要な操作に使う際は、媒体に応じて濃度を上げ、読めるコントラストを確保する。

## 4. Typography

本文と見出しは OS 標準のサンセリフを使う。外部フォントの読み込みに依存しない。

```css
font-family: "Helvetica Neue", Arial, "Hiragino Kaku Gothic ProN",
  "Hiragino Sans", "Yu Gothic", Meiryo, sans-serif;
```

番号、短いラベル、メタ情報、コードには `"Courier New", Courier, monospace` を使う。等幅フォントで長い日本語本文を組まない。

文字の比率を先に決め、絶対サイズは媒体と表示距離に合わせる。

| Role | Relative scale | Treatment |
| --- | --- | --- |
| Display | 本文の約 3.5–4.5 倍 | 短い主題。太字、詰めすぎない行間 |
| Heading | 本文の約 2–2.8 倍 | 区画の見出し |
| Lead | 本文の約 1.2–1.5 倍 | 主題を支える短い文章 |
| Body | 基準 | 読みやすい行長と行間を確保 |
| Label / Meta | 本文の約 0.7–0.85 倍 | 短い現在地、番号、注記 |

日本語の本文は一行が長くなりすぎないようにし、密な段落を連続させない。英数字と日本語の字面の差、改行位置、句読点のぶら下がりを実際の表示環境で確認する。強調語は太さやサイズ差で扱い、同じ区画で重ねすぎない。

## 5. Layout and rhythm

- コンテンツを一貫した左右の基準線に揃える。余白は画面幅や紙面に応じて伸縮させる。
- 主題の周囲には、ほかの要素から十分に離れた空間を確保する。補足は主題に近づけすぎない。
- 小さなラベルと細い水平線を組み合わせるときは、区画の現在地を示す目的で使う。
- 長い本文は読みやすい幅に絞る。広い面では段組みにするか、片側に余白を残す。
- 同じ種類の区画では、見出し位置、罫線、余白の間隔を揃える。
- 小さな画面では段組みを縦に並べ直し、情報の順序と余白の階層を維持する。

固定ヘッダーやフッター、特定の縦横比はこのデザインの必須条件ではない。必要な情報構造に合わせて適用する。

## 6. Patterns

### 主題と導入

短いラベルの後に大きな主題を置き、その下に一段小さい説明を添える。説明は主題を繰り返さず、文脈を補う。

### 要点一覧

三つ前後の並列項目は、番号・短いキーワード・説明の順で並べる。各行を細い罫線で区切り、個別のカードにしない。

### 時系列と手順

一本の水平線とノードで順序を示す。線の上に説明文を重ねない。項目が多い場合は、適切な区切りを設けるか縦の一覧へ切り替える。

### 比較

二つの対象を同じ基準線と上罫線で並べる。項目名や説明の位置を揃え、色面の違いに頼らず比較できるようにする。

### コードとコマンド

コードは本文とは別の対象として見せる。Code background の面に Code ink を使い、操作目的や短い補足を面の外に置く。長いコードは読みやすい幅に抑え、必要な部分を選ぶ。

### 図と画像

形と色の種類を抑え、本文と同じ基準線に揃える。写真や図は情報を伝える目的で使い、余白を埋めるためだけに置かない。

## 7. Motion and interaction

動きが必要な媒体では、状態の変化や順序を理解できる短い遷移を使う。装飾だけの反復動作は避ける。選択中の状態は色だけでなく、位置、線、太さなどでも判別できるようにする。

## 8. Avoid

- 丸角カードを並べたダッシュボード風の構成
- 意味のないグラデーション文字や蛍光色
- 見出し、バッジ、アイコン、脚注を同時に置く過剰なメタ情報
- 装飾用の矢印、アイコン、区切り記号
- 主題より強い影や背景テクスチャ
- 区画ごとに異なるフォント、マージン、罫線幅

## 9. Review

- 視線が現在地から主題、補足へ自然に移るか
- 余白、文字、罫線だけで情報の階層がわかるか
- 色と書体の使い方が上記の役割に一致しているか
- 小さな画面や異なる媒体でも読みやすさと情報順序を保てるか
- 装飾を取り除いても意味が通るか
